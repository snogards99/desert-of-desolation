# Stable 1.5.1 native production integration

The native checkout belongs to the existing Site; no replacement project or infrastructure was created. `site/native` records its buildable application source and locked dependencies. Unchanged public binary assets are identified by the byte manifest instead of duplicated in GitHub; the exact complete deployable source, including those assets, is pinned to the native Git commit in the production evidence. Unchanged public images, audio and fonts remain in the existing native source repository and are checked against native baseline commit `098b268939da8994f00bc8566840fa745b6d941d` by `NATIVE_PUBLIC_ASSET_SHA256.json`. Existing R2 objects are preserved; this source snapshot does not export all R2 objects.

Stable shared runtime modules were reconciled from plugin 1.5.1. Native-specific integration preserves the detailed existing character sheets, adds canonical alias normalization with no wrong-character portrait fallback, retains the native solar and confirmed-kill projection functions under native module names, and supplies type declarations for the packaged client. The native page adds top-level ChatGPT sign-in and secure UUID generation for the HTTP-only development preview. Production remains HTTPS.

Campaign access requires native dispatch identity. `DOD_CAMPAIGN_OWNER_EMAIL` is configured from the verified Site owner identity for existing, unclaimed campaigns. An authenticated owner’s first supported write atomically binds the canonical authenticated email subject in `campaign_owners`; subsequent access uses that subject. The actual native dispatch supplies `oai-authenticated-user-email`; no unsupported user-ID header is required. Missing configuration fails closed. Reads do not claim ownership or change campaign state. The Site audience remains public while campaign state requires its owner account.

`server-runtime/native-game.mjs` wires the published action-service contract to D1. Pure source resolution may run speculatively, but SQL revision and ownership guards serialize committed effects. One D1 batch atomically binds ownership and persists the guarded receipt, state and action journal. Ownership and revision predicates prevent unauthorized or stale effects; journal collisions roll back the entire batch. The journal insert is conditional on the immediately preceding state update changing exactly one row. Receipt replay rechecks authorization and exact fingerprints. Receipts are retained without expiry.

Only the previously implemented `prologue.charter.depart` transition is automatically resolved from the current source’s exact target. Other supported choices/free text are explicitly QUEUED, never reported as resolved; unknown choice IDs fail closed. No combat, resource, spell or treasure rule was invented. Queue persistence increments the storage revision and journal only. Two prologue scene audio bindings come from native AssetBundles (`context-parts/p931.json`); no missing narration is fabricated.

Run the native frozen-lockfile install, `tsc --noEmit --incremental false`, `npm run build`, then `node --test tests/*.test.mjs`. These tests use isolated Miniflare D1, including a built production Worker HTTP journey. Development previews use test identities only in temporary ignored setup; that setup and the 390px iframe harness are removed before packaging. No mock authentication or QA fixture is deployed.

Published plugin 1.5.1 remains immutable. Its bundled historical Site observations describe the pre-cutover release snapshot; current deployment authority is `release/UNIFIED_RELEASE_GUARD.json` and the coordinated production checkpoint. No plugin runtime or media is changed to append deployment evidence.
