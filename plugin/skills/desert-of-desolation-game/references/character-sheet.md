# Custom Party Master Sheets — Alpha 1
Follow AD&D 2E Character Sheet Rev 4.6 (Patrick M. Murphy, 7/98) as the structural reference.
On stats, statistics, character sheet or standalone sheet requests, show the selected actor's current record; default to Snogard. A Party request can show any of the six.
Use data/PARTY_SHEET_MASTER.json as a recorded baseline and data/PARTY_SHEET_TEMPLATES.json for actor-specific structure. Apply data/PARTY_ENRICHMENT_V2.json as the additive character-completion overlay. Mutable campaign state, runtime Characters, Inventory, SpellPreparation and SpellSlots override both baseline and enrichment overlay. Preserve campaign boundaries and stable actor IDs; party.tal has the explicit canonical alias party.talanis.
Render matching portrait from assets/character-sheet/manifest.json alongside structured values. Images are decorative original DOD_INK interpretations; they never establish race details, possessions, wounds or mechanics.
Always include identity/class/race/alignment, abilities, saves, HP, AC, THAC0, movement, initiative/attacks, proficiencies, class powers, equipment/resources, magic items, experience, conditions/effects, companions/mounts, party role, constraints/weaknesses and public notes.
Never display PSIONICS or FAMILY CHART for any actor.
Show spell preparation/slots/fetched magic only for actual casters or a clearly labeled verified-capacity-pending actor. Snogard uses the current runtime Cleric/Sha'ir state. Azhar, Dakarai and Eryon may show the enrichment overlay's spell-capacity audit and reference-only recommendations, but do not spend slots or activate a spell until the exact AD&D 2E class progression/access and the chosen spell are source-bound. Never import D&D 3.5 spell slots, DCs, ranges, class progressions or mechanics. Cyrra and Bar remain noncasters unless verified AD&D/campaign authority establishes otherwise.
Attached D&D 3.5 spell sheets are selection references only: they may suggest useful themes such as desert survival, detection, translation, traps, protection, healing and mobility. Map every activated choice to an AD&D 2E equivalent and verified class access first.
Show Thieving abilities for Cyrra and Ery when the actor's recorded skills are available. Runtime percentages override the master; retain recorded baseline notes for generated supplemental skills. Omit thief, turning-undead, martial-arts, reputation, honor or property sections when irrelevant or unrecorded.
For main campaign turning-undead sections apply to Snogard and Azhar; leave unbound target tables unknown. Use the actual recorded demo profile without importing main-campaign injury, spells, inventory or conditions.
Use lined parchment panels, serif headings and the shared ink art family; each actor has a unique portrait/accent. Stack on narrow screens, allow keyboard navigation and >=44px targets. Sheet views never post actions, spend resources, advance time or reset saves.
Unknown values use an em dash, never inferred rules values. Source-bound mechanics should be labeled clearly rather than omitted if the identity is established. Never expose private motives, future encounters, secret relic destinations, internal database IDs or source/provider URLs.

## Character enrichment overlay
`data/PARTY_ENRICHMENT_V2.json` records ten bounded enrichment passes for every active party member. Use it to fill party role, character utility, weaknesses, equipment doctrine, spell-status annotations and unresolved rules gaps without overwriting mutable state. A pass marked KEEP or VERIFIED_NO_CHANGE is complete; do not manufacture changes solely to satisfy the pass count.
